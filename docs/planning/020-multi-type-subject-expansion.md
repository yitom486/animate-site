## 问题摘要

应对齐的不是「把动画站功能原样复制五份」，而是 **Bangumi 官网每个板块菜单里已经有的那一套**：

> 近期注目 · 排行榜 · 分类浏览 · 标签 · **（该类型）日志**  
> 动画额外还有：每日放送

本站目前只把动画做得较完整（含 **动画日志** 列表 + 站内详情）；书籍/音乐/游戏/三次元导航过薄，且 **没有对应的板块日志**。  
用户与产品判断：**各板块日志与动画日志同等核心、非常有价值**——社区长文、书评、游记、影评是 Bangumi 区别于纯条目库的重要部分，值得优先站内化。

本规划以 **官网菜单为验收参照**，把可拉齐的项分期落地；**日志为最高优先级主线**。

## 为什么「板块日志」特别值得做

1. **内容价值高**：用户原创长文，信息密度远高于条目卡片与短评。
2. **与动画日志同构**：路径、`/feed/blog/{slug}`、单篇 `/blog/{id}`、列表 HTML 结构高度一致，**可参数化复用**现有 `blog/list.server.ts`、`blog/detail.server.ts`、`blog.tsx`、`blog-detail.tsx`，不是五套新系统。
3. **官网每个板块都有入口**：不做齐则本站对该类型「社区层」几乎空白。
4. **已有消毒与无限滚动经验**：风险主要在抽象参数与分页路径差异（如 `/book/blog` vs `/book/blog/N.html`），需在 PoC 时核对。

### 为何「书籍 RSS 看起来不如动画日志丰富」

对比的往往不是「book RSS vs anime RSS」（二者**字段同构**：约 12 条、`content:encoded`、作者、`pubDate` 同样常坏），而是：

| 体验来源               | 内容                                                                   |
| ---------------------- | ---------------------------------------------------------------------- |
| 本站「动画日志」       | HTML 分页列表（头像/时间/摘录）+ `/blog/{id}` 消毒详情 + 无限滚动      |
| 只看 `/feed/blog/book` | 短窗口最新稿 + 可能不准的日期 + 无头像；且 section feed 可能混入跨类型 |

所以丰富度差在 **管道（HTML 主路径）**，不在书籍格式先天更差。策略上应用枚举统一五类型，用同一套双源，而不是给书籍单独降级。

### 推荐数据策略（详情 / 列表）

1. **`BlogSection` 枚举**（`anime|book|music|game|real`）：路由、导航、返回文案、Referer、缓存 key 全走枚举。
2. **列表主源 = HTML** `/{section}/blog`（分页真相、头像与时间）。
3. **RSS = 加速层**：解析 `content:encoded`/`dc:creator`，按 `blogId` 写入短 TTL 正文缓存；打开详情时命中则少一次 HTML 抓取。
4. **分区校验**：RSS 条目须能在对应 section 的近期 HTML 列表中找到，否则不标成该类型（或仅进「全部」）。
5. **详情回落**：缓存未命中 → 抓 `/blog/{id}`（现动画详情）；再失败 → 摘要 + 原文链。
6. **时间**：忽略明显异常 `pubDate`（如 1970），优先 HTML 列表时间。
7. **单条目日志**：保留 `/subject/{id}/blog/rss` 作详情页侧栏（与板块 feed 分开）。

## 可做 vs 不做（相对官网「全部拉齐」）

| 官网能力             | 判定             | 说明                                 |
| -------------------- | ---------------- | ------------------------------------ |
| **各类型板块日志**   | **必做·优先**    | 与动画日志同价值；复用现有管道       |
| 近期注目 / 排行榜    | 已有·微调        | 核对与官网 trends/chart 语义         |
| 分类浏览             | **应做**         | 跟日志之后或并行小步；走 v0 subjects |
| 标签                 | **可做·后置**    | 需确认本站 tag 查询完整度            |
| 每日放送             | 仅动画           | 不扩展到其它类型                     |
| 人物 / 超展开 / 小组 | **不做（近期）** | 超出条目+日志范围，另立规划          |
| 登录收藏 / 章节管理  | **不做**         | 需登录态与写接口；本站只读公开       |
| 把 B 站/下载扩到全书 | **不做**         | 非官网该板块能力                     |

「全部拉过来」在本规划中的含义是：**五个条目板块的主导航能力（注目、排行、分类、标签、日志）+ 动画独有的放送**；不是把 Bangumi 整站（人物、小组、超展开、个人收藏）一次性搬空。

## 推荐方案

以官网为验收清单，分四期。**实现手法：枚举 + 传参复用同一套函数/页面，禁止按类型复制五份业务代码。**

```text
第 0 期  详情收敛（去穿帮）          ← 第一步（先完成）
   ↓
第 1 期  多类型板块日志（核心）
         BlogSection 枚举 + fetchBlog*(section, …)
   ↓
第 2 期  分类浏览 +（可选）标签
   ↓
第 3 期  详情信息增强 / 可选路由中性化
```

### 第 1 期实现约定（动手时遵守）

```ts
type BlogSection = "anime" | "book" | "music" | "game" | "real";

fetchBlogListPage(section: BlogSection, page: number)
fetchBlogSectionRss(section: BlogSection)
fetchBlogDetail(id: string) // 单篇跨类型，可不传 section
```

列表 HTML 为主、RSS 为正文缓存；路由/文案/缓存 key 均由 `section` 驱动。详情 UI 复用现有阅读页，去掉写死的「动画」文案即可。

### 第 0 期 — 详情收敛

- 非动画隐藏 B 站、下载；文案与外链按 type。
- **完成定义：** 书籍/游戏详情不再像「半个动画页」。

### 第 1 期 — 多类型板块日志（核心）

1. 抽象 `BlogSection = anime | book | music | game | real`（与官网 slug 一致）。
2. **双源：**
   - 列表分页：HTML（或确认分页形态后）——RSS 只覆盖最新一小窗，不够无限滚动。
   - 详情：优先若命中 RSS/`content:encoded` 缓存则消毒渲染；否则继续抓 `/blog/{id}`（现动画详情路径）。
3. 扩展 `parseRss2`（或专用 blog RSS 解析）取出 `content:encoded`、`dc:creator`/`author`。
4. 路由：`/anime/blog`、`/book/blog`…；详情倾向统一 `/blog/:id`（旧动画路径可重定向）。
5. 导航：每类型下拉加「××日志」；列表页内五类型切换。
6. **布局：** 不新开一套详情壳——复用现有 `blog-detail` 阅读页；只需去掉写死的「动画」文案、`SiteNav activeType`、返回链按 section 变化。正文仍是消毒 HTML + 现有 prose 样式（RSS 多为 `<br>`/链接，现选择器已覆盖）。
7. 与 [014](./014-blog-retry-and-infinite-list.md) 协调重试。

**完成定义：** 五类型均可站内浏览板块日志并打开正文；解析失败有明确空态；动画日志无回归。

### 第 2 期 — 分类 / 标签对齐官网

1. 对照 OpenAPI 配置各类型 `cat`；菜单增加「分类浏览」。
2. 评估 `/{type}/tag` 与本站 `view=tag`；能稳接再上「××标签」。
3. 游戏 `platform`、书籍 `series` 作为增强，不阻塞分类。

**完成定义：** 书籍/游戏/三次元至少具备可用的分类浏览；标签能做则做，不能则文档注明暂缓原因。

### 第 3 期 — 详情增强与工程整洁

- 关联人物/条目；卡片 staff 键按类型。
- 可选：`/anime` 路径中性化。
- 不把人物/小组等官网其它顶栏塞进本期。

## 风险与取舍

- **HTML 分页格式可能因类型而异**（`?page=` vs `N.html`）——第 1 期先做书籍 PoC 再铺开。
- 抓取依赖官网 DOM，存在改版风险；RSS 作校验与降级源。
- 日志内容版权与展示：继续摘要列表 + 消毒全文、保留原文链接（与现动画日志一致）。
- 五套路由若复制粘贴会失控——必须 **一个 list UI + section 参数**。

## 验证方法

- 对照官网：五类型下拉是否具备「日志」；分类/标签按当期范围验收。
- 每个 section 打开列表第 1 页与末页附近、点进至少 2 篇详情。

- 第 1 期完成后：书籍/音乐/游戏/三次元均有可用站内板块日志。

## 学习要点

- 官网「每个板块都有日志」说明日志是 **类型维度的社区产品**，不是动画特例。
- 单篇 URL 跨类型共用，列表按类型分区——站内路由应反映这一点。
- 「对齐官网」≠「克隆整站」；先条目导航 + 日志，再考虑人物/小组。
